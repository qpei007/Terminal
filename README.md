# Virtual Terminal

Виртуальный терминал — учебная объектно-ориентированная программа на C++, работающая с собственной внутренней моделью файловой системы. Программа моделирует терминал с поддержкой CRUD-операций для виртуальных файлов и директорий.

## Сборка и запуск

### Требования
- **Компилятор**: `g++` с поддержкой C++17
- **Система сборки**: `make`
- **ОС**: Linux (Ubuntu) / macOS / Windows (MinGW)

### Сборка
```bash
make all
```

### Запуск
```bash
./terminal
```

### Очистка
```bash
make clean
```

## Поддерживаемые команды

| Команда            | Описание                                               |
|--------------------|--------------------------------------------------------|
| `help`             | Показать список доступных команд                       |
| `exit`             | Завершить работу терминала                             |
| `ls`               | Показать содержимое текущей директории                 |
| `cd <dir>`         | Перейти в директорию (`..` — вверх, `/` — в корень)    |
| `cat <file>`       | Показать содержимое файла                              |
| `touch <file>`     | Создать новый файл (однострочный или многострочный)    |
| `mkdir <dir>`      | Создать новую директорию                               |
| `rm <name>`        | Скрыть файл или директорию (мягкое удаление)           |
| `restore [name]`   | Восстановить скрытую сущность (без аргументов — список)|
| `mv <old> <new>`   | Переименовать файл или директорию                      |
| `edit <file>`      | Редактировать содержимое файла                         |

### Особенности команд

- **`touch`**: при создании файла предлагает выбрать тип — однострочный (`SingleLineFile`) или многострочный (`MultiLineFile`).
- **`edit`**: поведение зависит от типа файла (полиморфизм):
  - `SingleLineFile` — запрашивает одну строку текста.
  - `MultiLineFile` — запрашивает несколько строк, ввод завершается командой `:wq`.
  - `Directory` — выводит ошибку (директории нельзя редактировать).
- **`rm`**: не удаляет сущность физически, а скрывает её (устанавливает флаг `hidden`).
- **`restore`**: без аргументов показывает список скрытых сущностей, с аргументом — восстанавливает указанную.

### Иерархия классов

```
Entry (базовый класс, НЕ абстрактный)
├── Directory          — директория, хранит дочерние Entry*
├── SingleLineFile     — однострочный текстовый файл
└── MultiLineFile      — многострочный текстовый файл
```

Все классы наследуются напрямую от `Entry` (плоская иерархия).

## Авторитативные архитектурные решения

### 1. Где хранится свойство скрытости
**Решение**: в классе `Entry` (поле `hidden`).  
**Обоснование**: скрытость — общее свойство для всех сущностей файловой системы. Хранение в базовом классе позволяет единообразно работать с этим свойством через полиморфные указатели `Entry*`, без необходимости приведения типов.

### 2. Где происходит фильтрация скрытых при `ls`
**Решение**: в методе `Directory::display()`.  
**Обоснование**: директория знает своих детей и отвечает за их отображение. Фильтрация скрытых при выводе — это ответственность директории, а не терминала. Terminal вызывает `cwd->display()`, не заботясь о деталях фильтрации.

### 3. Где реализован поиск сущности по имени
**Решение**: в методе `Directory::findChild()`.  
**Обоснование**: поиск среди дочерних элементов — естественная ответственность директории. Метод принимает параметр `includeHidden`, позволяющий искать и среди скрытых (для `restore` и проверки уникальности имени).

### 4. Как организован текущий путь (`cwd`)
**Решение**: комбинация указателя `Directory* cwd` и `vector<string> pathParts`.  
**Обоснование**: указатель `cwd` обеспечивает быстрый доступ к текущей директории, а `pathParts` используется для формирования строки промпта. Такой подход проще, чем вычисление пути через цепочку `parent`-указателей, и обеспечивает O(1) доступ к текущей директории.

### 5. Как устроен переход между директориями
**Решение**: при `cd <dir>` — находим дочернюю директорию через `findChild`, обновляем `cwd` и добавляем имя в `pathParts`. При `cd ..` — переходим к родителю через `getParent()` и удаляем последний элемент `pathParts`.  
**Обоснование**: синхронное обновление указателя и вектора пути обеспечивает согласованность состояния. Попытка подняться выше корня обрабатывается явной проверкой `cwd == root`.

## Полиморфизм в программе

Ключевые виртуальные методы класса `Entry`:
- **`display()`** — разное отображение для файлов и директорий
- **`edit()`** — разное поведение редактирования для типов файлов
- **`isDirectory()`** — определение типа без `dynamic_cast`
- **`asDirectory()`** — безопасное приведение к `Directory*`
- **`displayName()`** — директории отображаются с `/`, файлы — без
- **`getType()`** — строковый тип для информативного вывода

Terminal работает с сущностями через указатели `Entry*` и никогда не проверяет конкретный тип объекта через `if`-цепочки. Всё поведение определяется через виртуальную диспетчеризацию.
